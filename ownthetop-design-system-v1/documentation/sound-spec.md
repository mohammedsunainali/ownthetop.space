# OwnTheTop Sound Specification V1

Status: **SPECIFICATION ONLY**. No audio file in this document is claimed as generated or licensed.

## Principles

Sound should reinforce state, height and motion without turning the product into a game. It is optional, user-controlled and disabled by reduced-sensory preferences where appropriate.

## Interaction

| Event | Direction |
|---|---|
| hover | very short airy tick; desktop only; subtle |
| click/select | soft tactile digital click |
| success | bright two-note lift |
| error | short low muted knock; no harsh alarm |

## Construction

| Event | Direction |
|---|---|
| build | compact layered construction pulse |
| floor-rise | rising airy sweep with restrained mechanical body |
| tower-grow | deeper extension of floor-rise, reserved for meaningful growth |
| rank-change | small directional tick; pitch can follow up/down movement |

## Signature moments

### Outbid

A short descending cue; cheeky, not humiliating or alarming.

### #1 / Own the Top

Sequence:
1. environment lowers slightly
2. ascending tonal sweep
3. concise summit hit
4. optional short celebratory tail

Avoid generic casino, slot-machine or esports victory language.

## Environment

Day:
- soft wind
- distant city
- sparse birds
- occasional aircraft

Night:
- softer wind
- distant city bed
- aircraft/rooftop light ambience implied through sound sparingly

## Humor

Optional rare cues:
- record-scratch-like original effect
- goofy pop
- restrained airhorn-inspired cue

Use only for editorial moments or opt-in easter eggs. Do not fire these on normal payment errors.

## Product controls

Users need a clear global sound toggle. Environment layers should be independently configurable in the longer-term environment panel, but V1 may group ambient layers if implementation scope requires it.
