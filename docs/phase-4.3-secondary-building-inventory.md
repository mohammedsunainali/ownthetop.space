# Secondary district inventory — demo previews only

Existing neighborhood grid IDs (`district-column-row`) are stable across sorting and desktop/mobile truncation. `domain/district-building.ts` separates decorative/preview from verified commercial availability/reservation/occupancy. Current `district-inventory.ts` contains **only** decorative and preview states. Names are fictional demo architecture labels, not sponsors or endorsements. No pricing, duration, fulfillment, payments or legal ownership is implemented.

Canonical world store selects one secondary ID and clears tower listing selection. Tower/floor/reset/top/Crown transitions clear secondary identity. `CameraController` has a separate districtBuilding mode with geometry-derived fit, normal wheel zoom, orbit and toolbar zoom. Main tower traversal contract remains unchanged. `DistrictBuildingPanel` provides accessible inventory selection and an unpaid name preview; `BuildingPreviewSign` mounts one disposable canvas texture on the selected storefront. Existing instanced shop bodies are clickable. Decorative buildings cannot enter inventory selection.

Five domain/store tests cover stable IDs, honest labels, no paid/available fixtures, exclusive listing identity, reset, invalid/decorative rejection. Automated tests pass; actual production click/preview/focus inspection remains pending. Secondary-building collision/occlusion handling is not yet generalized to the same level as primary tower inspections; do not call every secondary orbit safe until tested. Real booking remains gated on explicit business approval of pricing, duration, moderation, fulfillment and cancellation/refund policies.
